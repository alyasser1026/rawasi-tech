# برومتات تطوير بوت فاي تك — لكل مرحلة

الملف المرجعي: `claude/bot-upgrade-plan.md` في المشروع. كل برومت يُلصق في جلسة جديدة.

| المرحلة | الموديل المفضل | المستوى |
|---|---|---|
| 1 — تثبيت القائمة والأزرار | Sonnet | Medium |
| 2 — أزرار تحت التقارير | Sonnet | Medium |
| 3 — التنبيهات الاستباقية | Opus | High |
| 4 — التقارير المجدولة | Sonnet | Medium |
| 5 — السياق والتأكيد بخطوتين | Opus | High |
| 6 — الصلاحيات والسجل | Opus | Max (أمان) |

قاعدة الاختيار: Sonnet للمهام اللي بتتبع نمطًا موجودًا في الكود (أزرار، جدولة). Opus للمهام اللي فيها تصميم حالة أو منع تكرار أو أمان أو كتابة في قاعدة البيانات.

## قيود مشتركة (تُضاف أول كل برومت)

```
المشروع: D:\my-accounting-app (بوت تلغرام في scripts/telegram-copilot.mjs و copilot-*.mjs).
- ممنوع قراءة أو طباعة أو commit لأي ملف .env أو .env.local، ولا تطبع أي سر.
- لا commit ولا push ولا تعديل على قاعدة البيانات إلا لو طلبت صراحة.
- الرد بالعربي المصري ومختصر.
- قبل التعديل اقرأ النسخة الحالية من الملف (لا تعتمد على نسخة قديمة)، وبعد التعديل شغّل node --check على كل ملف اتغيّر.
- شغّل اختبارات البوت (scripts/copilot-mock-test.mjs والاختبارات الموجودة) وتأكد إنها ما اتكسرتش.
- غيّر أقل قدر ممكن من الملفات، واتبع نمط الكود الموجود (handleCallbackQuery, sendTelegramMessage, createCopilotTools).
- في الآخر اكتب لي: الملفات اللي اتعدلت، وإزاي أختبر على تلغرام، وهل يلزم إعادة تشغيل البوت.
```

## المرحلة 1 — تثبيت القائمة والأزرار (Sonnet / Medium)

```
[القيود المشتركة]
المهمة: القائمة الرئيسية اتضافت (MAIN_MENU_ACTIONS و buildMainMenuMarkup و /menu و registerBotCommands). راجعها وثبّتها:
1) تأكد إن كل جملة في MAIN_MENU_ACTIONS بتفعّل أداة صح في copilot-tool-registry.mjs. لو جملة ما بتطابقش أي أداة، عدّلها لجملة بتشتغل أو ضيف الأداة المناسبة.
2) أضف حالة اختبار لكل زر في copilot-mock-test.mjs (الزر يمرّر الجملة لنفس مسار الرسائل ويرجع رد).
3) تأكد إن الأزرار شغالة في الخاص وفي المجموعة المشتركة، وإن /menu@اسم_البوت بيشتغل.
4) لا تغيّر أي سلوك تاني.
```

## المرحلة 2 — أزرار تحت التقارير (Sonnet / Medium)

```
[القيود المشتركة]
المهمة: أضف أزرار متابعة تحت رد التقرير اليومي (get_daily_comprehensive_report) وتقرير الإضافات المتأخرة:
- «تفاصيل أكتر»، «تقرير الأسبوع»، «ملف PDF»، «الإضافات المتأخرة»، «القائمة الرئيسية».
- كل زر callback_data بصيغة report:<action> ويتعالج في handleCallbackQuery ويستخدم نفس الأدوات والصلاحيات.
- الأزرار تظهر تحت آخر رسالة من التقرير فقط، مش تحت كل جزء.
- زر PDF يعيد استخدام مسار PDF الموجود (copilot-pdf-requests.mjs) بدون كود جديد لتوليد الملفات.
- اكتب اختبار لكل زر، وتأكد إن multi_messages ما اتكسرتش.
```

## المرحلة 3 — التنبيهات الاستباقية (Opus / High)

```
[القيود المشتركة]
المهمة: ابنِ نظام تنبيهات استباقية للبوت. صمّم قبل ما تكتب كود واعرض عليّ التصميم في 10 أسطر، وبعد موافقتي نفّذ.
الأنواع المطلوبة: مستخلص مقاول متأخر، رصيد خزنة تحت حد، أمر شغل تجاوز موعده، حركة مالية كبيرة غير معتادة.
المتطلبات:
- فاحص دوري (مثل startDailyReportScheduler) بتوقيت الرياض، قراءة فقط من قاعدة البيانات، بنفس مسار الصلاحيات والشركة النشطة.
- منع التكرار: حفظ حالة آخر تنبيه لكل (النوع + المعرّف) في ملف إعدادات البوت أو جدول، وما يتكررش قبل مدة قابلة للضبط.
- إعدادات تشغيل/إيقاف لكل نوع وحدود الأرقام، تتغيّر من رسالة الإعدادات الموجودة (buildSettingsMessageAndMarkup).
- ساعات هدوء (مثلًا بعد 10 مساءً وقبل 7 صباحًا) ما يتبعتش فيها غير الطوارئ.
- كل تنبيه ليه أزرار: «تفاصيل» و«كتم هذا النوع».
- الافتراضي: كله مطفي لحد ما أشغّله.
- اكتب اختبارات للمنطق (الشرط، منع التكرار، ساعات الهدوء) بدون اتصال حقيقي بتلغرام أو قاعدة البيانات.
لو محتاج جدول جديد في Supabase، اكتب ملف SQL في work/ وما تطبّقوش.
```

## المرحلة 4 — التقارير المجدولة (Sonnet / Medium)

```
[القيود المشتركة]
المهمة: وسّع الجدولة الحالية (startDailyReportScheduler) لتشمل: ملخص صباحي، تقرير أسبوعي (الخميس)، تقرير شهري (أول يوم في الشهر عن الشهر السابق).
- كل تقرير له إعدادين في copilot-bot-settings.mjs: تشغيل/إيقاف ووقت الإرسال (توقيت الرياض).
- استخدم أدوات التقارير الموجودة، وإن ما كانتش موجودة للأسبوع/الشهر ضيف أداة قراءة فقط بنفس النمط في copilot-tools.mjs.
- منع الإرسال المكرر لنفس اليوم/الأسبوع/الشهر حتى بعد إعادة تشغيل البوت.
- الإرسال بنفس مسار splitReportParts و multi_messages.
- تعديل المواعيد من رسالة الإعدادات بأزرار.
- اكتب اختبار على حساب التواريخ (حدود اليوم والأسبوع والشهر بتوقيت الرياض).
```

## المرحلة 5 — السياق والتأكيد بخطوتين (Opus / High)

```
[القيود المشتركة]
المهمة: (أ) سياق أسئلة المتابعة: «وكام للمقاول ده؟» تفهم إن المقصود آخر مقاول/مشروع اتذكر، باستخدام copilot-conversation.mjs (remember) مع مهلة انتهاء. (ب) أي عملية كتابة (قيد، أمر شغل، يومية، مصروف) تتنفذ بخطوتين: البوت يعرض ملخصًا بالقيم النهائية وزرين «تأكيد» و«إلغاء»، والتنفيذ لا يحصل غير بعد التأكيد.
متطلبات الأمان:
- التأكيد مربوط بالمستخدم والمحادثة وبمعرّف عملية واحدة الاستخدام، ويسقط بعد مدة، ولا يمكن إعادة تشغيله بضغطتين.
- الملخص المعروض هو نفسه اللي يتنفذ بالضبط (لا إعادة تفسير للنص بعد التأكيد).
- لو الأرقام أو الأسماء غامضة يسأل بدل ما يخمّن.
- اتبع نظام المسودات والأرقام التسلسلية الحالي (entry forms) بدل ما تبني نظام موازي.
اعرض عليّ التصميم المختصر قبل التنفيذ، واكتب اختبارات للحالات: ضغط مزدوج، تأكيد منتهي، مستخدم تاني يضغط، تعديل بعد العرض.
```

## المرحلة 6 — الصلاحيات والسجل (Opus / Max)

```
[القيود المشتركة]
المهمة: صلاحيات لكل مستخدم تلغرام وسجل تدقيق وحد للطلبات.
- مراجعة copilot-telegram-auth.mjs و copilot-company-access.mjs وحدّد الوضع الحالي، واعرضه عليّ في نقاط قبل أي تعديل.
- أدوار (مدير، محاسب، مهندس موقع، قراءة فقط) بحيث كل دور يرى ويكتب في أدوات معيّنة فقط، وتُطبَّق في runEnabledCopilotTool وليس في الأزرار فقط.
- سجل تدقيق لكل طلب ينفّذ كتابة أو يقرأ بيانات مالية: المستخدم، الوقت، الأداة، ملخص بدون أسرار أو أرقام حسابات.
- حد معدّل للطلبات لكل مستخدم مع رسالة واضحة.
- فحص أمني: حقن في النصوص، تخطي الأزرار عبر callback_data مزوّرة، تسريب بيانات شركة لشركة أخرى، وأي مسار يستخدم service role بدون تحقق.
- لو يلزم جدول أو سياسات RLS اكتب ملف SQL في work/ وما تطبّقوش.
- الناتج: تقرير بالثغرات والإصلاحات، واختبارات تثبّت كل إصلاح.
```
